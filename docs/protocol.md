## 1. 一页概览

**研究问题：在几个近期 TFM 的固定配置中，逐任务选择模型，是否比一直使用同一个模型有实际价值？这种价值能否通过验证反馈获得？**

建议核心规模：

- 3 个模型家族：TabPFN-3.5、TabICLv2、LimiX-2。
- 6 个完整小数据集：2 个二分类、2 个多分类、2 个回归。
- 每个数据集 3 个预先固定的外层划分。
- 共 3 × 6 × 3 = **54 个模型评测单元**。
- 每单元：固定训练上下文，分别生成验证和测试预测。一次单元不是一次神经网络前向，也不一定等于一次 `fit`。
- 先完成 6 个接通单元，再补到 18 个首划分单元，最后补齐 54 个。
- 固定单模型、验证集选择、随机选择期望、事后 Oracle 和成本分析均复用这些预测。
- 先分析官方缓存成绩，新增 TFM 计算量为零；缓存分析与本地实验分开报告。
- 本轮不需要训练 LLM 路由器，不需要 HPO、微调、跨模型 ensemble 或自迭代。

可信度边界：6 个数据集足以做开发阶段的方向筛查，不能承诺统计功效，也不能证明对表格任务总体的泛化。更多随机种子不能替代更多独立任务。

## 2. 目的与假设

| 编号 | 假设/问题 | 观察证据 | 对研究方向的作用 |
| --- | --- | --- | --- |
| H1 | 模型存在有实际幅度的任务间互补 | Oracle 与事后最佳固定模型的差距；模型间的稳定胜负反转 | 判断是否值得研究质量导向路由 |
| H2 | 互补不完全由任务类型解释 | 二分类、多分类、回归分别计算选择收益；同一类型内的赢家是否改变 | 排除仅按任务类型选择就足够的解释 |
| H3 | 不看测试答案，验证反馈能获得一部分收益 | 验证集择优模型在测试上的成绩 | 检查任务内反馈的实用性；不代表 LLM 已有效 |
| H4 | 即使质量差异不大，也可能有质量—时间取舍 | 近似同等质量下的速度差异；超时/OOM；峰值显存 | 判断预算约束选择是否更值得推进 |

对照解释：

- H1 不成立：这个候选池和小数据范围中，复杂路由可能没有足够收益。
- H1 成立、H3 不明显：可能存在难以识别的赢家，或验证集太小、噪声太大。
- H3 成立：支持“反馈具有信息价值”，尚不支持“LLM 比简单选择器好”。
- H4 成立：可以继续研究质量要求与资源预算共同决定的选择问题。

本轮不检验：学得的路由器能否跨任务泛化、LLM 是否必要、ensemble 是否有效、self-evolution 是否有效。

## 3. 模型与配置

### 3.1 三个核心模型

| 标识 | 模型版本 | 权重/配置 | 本轮定位 |
| --- | --- | --- | --- |
| PFN35 | TabPFN-3.5 标准版 | `tabpfn-v3.5-20260909.safetensors`；该版本官方标准推理配置 | 强固定参照；不使用 Thinking 或 Fast 变体 |
| ICL2 | TabICLv2 | 分类 `tabicl-classifier-v2-20260212.ckpt`；回归 `tabicl-regressor-v2-20260212.ckpt`；`n_estimators=8` | 第二个模型家族 |
| LIMIX2 | LimiX-2 | `stable-ai/LimiX-2` 中的 `LimiX-2.ckpt`；分类 `cls_default_noretrieval_v2.json`；回归 `reg_default_noretrieval_v2.json` | 第三个模型家族；不能与 LimiX-2M 混淆 |

以上接口和权重名称已从官方代码/模型卡核查；尚未下载权重、核查本地访问权限或在 4090 上实测。

来源：[TabPFN 官方代码](https://github.com/PriorLabs/TabPFN)、[TabICL 官方代码](https://github.com/soda-inria/tabicl)、[LimiX-2 模型卡](https://huggingface.co/stable-ai/LimiX-2)。

### 3.2 为什么用标准配置

本轮缩减数据规模、候选数和划分数；保留官方固定推理配置。否则，任意把某个模型的内部成员数砍成 1，可能人为改变排名。

这些模型内部可以包含多个输入变换或预测成员。这与未来 harness 做跨 TFM ensemble 是不同层面的操作。54 个评测单元已经包含各模型官方配置所需的内部计算。

执行前冻结：

- Python 包版本或代码 commit；
- checkpoint 名称、revision 与 SHA256；
- 完整推理配置及其哈希；
- 实际解析后的内部成员数、精度模式、设备；
- 分类/回归的输出约定及类别顺序。

TabPFN 的 `n_estimators="auto"` 需解析并记录具体值，不能仅保存“默认”；LimiX 保存完整 JSON。首次成功接通后，不再自动升级依赖或改动配置。

不同模型默认计算量不相等。因此本轮结论是“固定官方配置的质量—成本比较”，不能声称严格等 FLOPs 或等时长比较。

### 3.3 暂不增加的模型

先不加 TabFM、Causilo、AutoGluon、CatBoost，也不比较多种 LLM。这样能够隔离三个 TFM 家族本身的选择空间。

加入一个常量预测器仅用于归一化与数据检查：分类输出训练类频率，回归输出训练目标均值；不占用 GPU。

若新版权重访问或安装受阻，先处理接通问题。旧版可用于单独的工程演示，但不得把旧版结果填进以上模型对应的实验行。

## 5. 先用已有成绩检查整体空间

### 5.1 低成本预检查

TabArena 官方提供逐配置成绩缓存，并提供 `run_export_results_per_split.py` 导出逐数据集/划分结果。只读取成绩层，不下载大型预测缓存；不启动 TFM 训练或推理。

来源：[官方成绩导出脚本](https://github.com/autogluon/tabarena/blob/main/examples/plots/run_export_results_per_split.py)、[缓存层级说明](https://github.com/autogluon/tabarena#-tabarena-artifacts)。

固定规则：

- 先列出三个确切模型版本是否可用，以及对应的是 default、tuned 还是 ensemble。
- 优先使用可比的默认配置；不可比配置分开列出，不混成同一结论。
- 只在共同有效数据集/划分上比较质量，同时报告覆盖范围。
- `imputed=True` 的填补成绩不能视为该模型实际完成的预测。
- 不把不同硬件上的官方耗时当作本地成本比较。
- 本地配置不同、训练集规模不同或内部验证方式不同，则不能合并缓存与本地成绩。
- 若确切版本没有缓存，明确缺失，继续本地实验；不为追求齐全而重跑全部 51 个数据集。

输出：模型覆盖表、逐任务胜负、Oracle 差距、类型内差距和失败/填补情况。

目的：以低计算成本获得比 6 个任务更宽的背景证据。公开缓存成绩已经被分析过的任务，不能再称为完全未见的最终评测任务。

## 6. 数据划分与一次单元的执行

### 6.1 固定外层划分

从每个 OpenML Task 获取官方外层 split：

- S0：`repeat=0, fold=0, sample=0`
- S1：`repeat=1, fold=0, sample=0`
- S2：`repeat=2, fold=0, sample=0`

TabArena 原始协议使用重复三折外层划分；这里仅取三个 repeat 的第一个 fold。执行前检查所选 Task 确实提供这些索引；若接口不可用，先解决数据访问，不静默换为随机划分。

来源：[TabArena §2.3](https://arxiv.org/html/2506.16791v4#S2.SS3)。

每次取官方外层训练部分，再切出其中 20% 作内部 validation：

- 分类按目标分层；
- 回归普通随机划分；
- 对应随机种子为 20261020、20261021、20261022；
- 同一数据集和 split 下三个模型必须共用完全相同的行索引。

大致比例为：约 53.3% fit、13.3% validation、33.3% test。按库实际取整记录准确行数。

本轮不在模型选定后用 fit+validation 重训：三个模型都始终使用同一 fit 上下文，节省计算并保持选择前后预测对象一致。因此本轮是“TabArena 数据与外层划分上的简化 pilot”，不是完整官方排行榜复现。

### 6.2 单元定义

一个单元由 `(dataset_id, outer_split, model_version, config_hash)` 唯一确定：

1. 加载本地预下载权重。
2. 使用 fit 部分建立模型上下文/拟合允许的变换。
3. 对 validation 单独预测，保存结果和计时。
4. 对 test 单独预测，保存结果和计时；标签只交给评分程序。
5. 保存状态、环境、资源和预测文件。

LimiX 等接口可能在每次 `predict` 中重复处理训练上下文；实际成本全部计入，不能因为没有传统训练循环就记为零。

### 6.3 数据访问边界

| 对象 | 可访问 |
| --- | --- |
| 模型拟合/训练上下文 | fit 的 X、y |
| 验证选择器 | validation 预测、标签、成本；不能访问 test |
| 模型测试推理 | fit 上下文与 test 的 X；不能访问 test 的 y |
| 最终评分程序 | test 标签与已经固定的预测/选择结果 |
| 全局 memory/ToolCard | 本轮最终测试成绩不回写为后续泛化评测的先验 |

validation 与 test 分开调用，不把两个查询集拼接后共同预测，以免验证结果受到测试协变量影响。

外层编码器/填补器只能在 fit 上拟合。模型内部如有使用当前查询 X 的无监督预处理，必须审查并记录为 transductive 行为，不能写成完全归纳式；仍不得读取查询 y，也不得将 validation 和 test 合并预处理。缓存 key 必须含数据、split、fit 行、查询分区和配置，避免跨划分串用。

### 6.4 预处理与预测核对

- 按官方 metadata 分离类别/数值列；保留原始语义类型。
- 优先使用模型官方内置预处理，不能强行对所有模型统一 one-hot 或标准化。
- 如果适配器需要类别编码，用 fit 学映射，未知类别/缺失单独处理，传递类别列索引。
- 目标类别映射在 fit 上建立，三模型概率列统一对齐；检查 test/validation 中类别是否被 fit 覆盖。
- 回归预测还原到原始目标单位。
- 检查概率有限、每行和接近 1；计算 log-loss 时统一截断至 `[1e-7, 1-1e-7]` 并重新归一化。
- 不把 id/目标列作为特征；遵守 Task 指定的 ignore/row-id 列。
- 锁定模型随机种子为 42；三个 outer split 主要检查数据划分敏感性，本轮不做数据种子 × 模型种子的完整网格。

## 7. 指标与对照

### 7.1 主指标

| 类型 | 主指标 | 越好方向 | 转成损失 L | 附加指标 |
| --- | --- | --- | --- | --- |
| 二分类 | ROC-AUC | 越大越好 | `1 - AUC` | Accuracy、log-loss |
| 多分类 | log-loss | 越小越好 | log-loss | Accuracy、macro-F1 |
| 回归 | RMSE | 越小越好 | RMSE | MAE、R² |

主指标与 TabArena 常用评价口径一致。选择模型只能使用预先指定的主指标，不根据结果切换“最有利指标”。

### 7.2 五种分析方式，复用同一批预测

1. **Fixed-PFN35**：所有任务固定 TabPFN-3.5。预先固定的强参照，不声称一定是本轮最强。
2. **Fixed-ICL2** 与 **Fixed-LIMIX2**：其余固定模型；完整显示每一个。
3. **ValSelect**：每个 split 用 validation 主指标选一个模型，直接采用它已经产生的 test 预测。分数完全相同按固定模型顺序 PFN35、ICL2、LIMIX2 打破平局。
4. **RandomSelect 的期望成绩**：三个模型损失的算术均值，表示均匀随机选一个模型的期望；不平均预测，不额外重复随机实验。
5. **Oracle**：事后看 test 表现才知道的理想选择。用于计算选择空间，不能作为可部署方法。

其中 ValSelect 是诊断“验证反馈是否有用”的离线对照。如果正式工作继续采用测试任务上冻结、只路由的协议，ValSelect 只能作为额外反馈对照，不能伪装为无反馈路由。

### 7.3 选择空间的计算

不能直接平均不同单位的 AUC error、log-loss 与 RMSE。

对每个数据集 d、划分 s：

- 常量分类器采用 fit 类频率（Laplace +1 平滑），回归采用 fit 目标均值。
- 用相同评价分区计算常量模型损失 `L0[d,s]`。
- 定义归一化损失 `e[d,s,m] = L[d,s,m] / max(L0[d,s], 1e-12)`。
- 二分类常量预测的 `1-AUC=0.5`；其他两类基线在相同分区实算。
- 先平均三个划分，得到 `E[d,m] = mean_s e[d,s,m]`。

描述性指标：

```text
SBS = min_m mean_d E[d,m]
VBS = mean_d min_m E[d,m]
G_all = (SBS - VBS) / max(SBS, 1e-12)
```

SBS 是在这些结果上事后挑出的最佳固定模型；VBS 是每个数据集事后挑一个最佳模型。这里先对划分取平均，再选数据集赢家，避免把每次偶然的随机赢家都计成可利用的任务差异。

另外按二分类/多分类/回归分别计算 SBS，并以数据集等权合并为 `SBS_type`：

```text
G_type = (SBS_type - VBS) / max(SBS_type, 1e-12)
```

`G_type` 更接近“知道任务类型后，还需要按具体数据集选择吗”。SBS/VBS 都是事后描述，存在选择乐观偏差；差距不是实际路由收益。

ValSelect 的收益单独在 test 上相对各个固定模型报告；主要预设参照为 Fixed-PFN35。若它仅优于 PFN35、未优于另一个固定模型，不得写成“路由优于最佳单模型”。

### 7.4 成本指标

每个单元记录：

- 权重加载时间；
- 外部与内部预处理、fit 时间；
- validation/test 预测时间；
- 完整单元 wall-clock 时间；
- GPU 峰值显存、可获取时的进程峰值 RAM；
- 成功、超时、OOM、错误；
- 实际内部成员数与精度配置。

需要 CUDA 同步后计时。首次网络下载不进入预测耗时，单独记录准备成本；本地权重加载计入冷启动成本。

分别报告：

- 冷启动单任务：模型加载 + fit/预处理 + test 预测；
- 已加载模型的任务成本：fit/预处理 + test 预测；
- 诊断搜索成本：三个模型各自加载/fit + validation，再加所选模型 test 推理。若官方调用重做上下文，按实际过程计算；从缓存推算的流程成本标为估算。

所有模型的 test 预测为本次离线研究开销；它们并非 ValSelect 部署时都必需，但也不能在“本次实际算力支出”中删除。

质量—成本同时给出图，不先把两者压成任意加权总分。

## 8. 可信度与决策规则

### 8.1 最小可信度要求

- 同数据、同索引、同预算边界的配对比较。
- 每个数据集展示三个划分原始值、平均值和标准差；标准差不是 95% 置信区间。
- 先合并划分，再讨论跨数据集结果。独立任务数是 6，而不是 18，更不是 54。
- 六个数据集为有目的的小数据覆盖，不是从所有表格任务中随机抽样；不能把区间解释为全领域的保证。
- 不以单次冠军作为某模型“生态位”的证据。

可额外做零 GPU 开销的敏感性分析：

1. 在每个任务内，S0 的 test 预测做 2,000 次配对行 bootstrap，分类分层抽样，三个模型共用采样索引，得到两两差异的条件性区间。它只反映当前训练模型下的测试样本不确定性。
2. 对跨任务平均改善，以整个数据集为抽样单位做 2,000 次 bootstrap，数据集的三个 split 保持一起。n=6 时只作为稳定性参考，不用其“是否跨零”作唯一 go/no-go 判定。
3. 不报告“54 次独立实验显著优于”；本轮不做靠多重比较筛出显著赢家的结论。

### 8.2 预先设定的实用差异阈值

这些是项目的筛查标准，不是文献公认阈值，也不是功效分析得到的数值：

| 主指标 | 暂定“有实际幅度”的改善 |
| --- | --- |
| 二分类 AUC | 绝对提高至少 0.005 |
| 多分类 log-loss | 相对降低至少 2% |
| 回归 RMSE | 相对降低至少 2% |

“稳定的任务优势”暂定义为：三个 split 至少两个方向相同，且三次平均达到上述实际幅度。必须展示第三个 split 的反例；不称为统计显著。

### 8.3 完成核心 54 单元后的一次决策

| 结果 | 下一步 |
| --- | --- |
| `G_type >= 2%`，至少两个任务出现达到实用阈值的替代优势，且涉及至少两个赢家 | 进入路由候选比较，保留完整三模型池 |
| Oracle 有空间，但 ValSelect 也很难获得收益 | 先诊断验证噪声/任务差异，最多加入预设两个扩展任务；不要立即训练复杂 LLM 路由器 |
| `G_type < 1%`，且没有稳定的实用胜负反转 | 暂不继续堆质量路由；结合缓存广域证据判断是否转向成本/配置选择 |
| 介于上述区间，或收益仅由一个任务驱动 | 标记“不明确”，仅做预设扩展，总量最多 72 |
| 有模型在主指标容差内、总时间至少快 2 倍，并在至少两个任务重复出现 | 支持进一步研究预算约束选择，即使纯质量 Oracle 差距较小 |

质量容差使用同一张阈值表；成本判定需成功完成的同硬件记录。失败模型不能成为速度冠军。

两个扩展任务跑完仍不明确，停止本轮，保留“不足以判断”的结果。不得不断添加数据集直到出现想要的结论。

上述阈值仅控制后续投入，不能替代论文统计结论。核心结果与扩展结果分开列出。

## 9. 运行顺序与预算

| 阶段 | 工作 | 新增正式单元 | 累计正式单元 |
| --- | --- | ---: | ---: |
| P0 | 导出官方缓存成绩，完成覆盖审查 | 0 | 0 |
| P1 | D1 与 D5 的 S0，三个模型各跑一次；检查分类/回归路径 | 6 | 6 |
| P2 | 其余四个数据集 S0 | 12 | 18 |
| P3 | 六个数据集的 S1、S2 | 36 | 54 |
| P4，可选 | 两个预设扩展任务 × 三模型 × 三划分 | 18 | 72 |

P1/P2 只做接口、资源和数据检查，不因当前 test 冠军不符合预期而改配置或换数据。固定方案后完整跑完核心 54 单元再作质量方向决策。

### 9.1 硬预算建议

- 每个评测单元独占一张 4090。
- 每单元 wall-clock 上限 **20 分钟**，包含本地模型加载、fit、validation 和 test 推理；不含预下载。
- 核心正式上限：54 × 20 分钟 = **18 GPU 小时**。
- 可选扩展上限：增加 **6 GPU 小时**。
- 另给工程诊断/修复后重跑最多 **2 GPU 小时**；真实开销单列。
- 这是分配上限，不是已测运行时间，也不是承诺完成时间。

开始用 3 张 GPU，每张串行跑一个单元；数据和权重预缓存后，如 CPU/RAM 够用再扩并发。不需要把一个模型拆到 10 张卡上。

同一个 `(dataset, split)` 的三个模型尽量在同一张卡上顺序运行，次序使用固定种子随机化，减少卡间差异。任务之间并行，避免同一 GPU 同时跑两个候选。

### 9.2 失败处理

- 权限、数据下载或安装问题记为准备阶段问题。
- 单元中 OOM、超时、无效概率等记为失败，保留日志与已用时间。
- 不为失败模型偷偷减少特征、样本或内部成员数。
- 如发现适配器 bug，版本号改变；所有受影响结果作废并在明确预算内重跑，不能只重跑差的结果。
- 质量汇总给出三模型共同成功的范围，同时展示完整成功率矩阵；失败不能默默删除，也不能伪造为一个正常损失。
- 若核心实验不能获得完整 54 个有效单元，报告实际覆盖；不要按计划数声明完成。

## 11. 如何接到后续 LLM harness

54 个单元为完整三模型池提供了可复用结果：

- 若后续 LLM 只从三个完全相同的配置中选择，可以离线回放其选择并读取对应预测，无需重新调用 TFM。
- LLM 输入可以是 fit 数据摘要、任务主指标、预算和冻结 ToolCard。
- 摘要/ToolCard 的变化导致不同路由决策时，评估成本主要是 LLM 调用和离线计算。
- 模型、训练上下文、预处理、查询分批或超参数改变后，旧预测不能当作新配置结果。
- 如果研究真实在线成本，需要对少量完整流程实际计时；缓存回放不能宣称省掉了部署时所需的模型推理。

本轮结果打开后，这 6 个任务就是开发任务。后续可以用它们调 prompt 或学习经验，但正式泛化结论必须使用另行冻结、未用于选择策略的任务。

若正式协议不允许测试任务候选试跑，则 LLM 的决策在任何该任务的验证模型分数可见之前固定；ValSelect 保持“允许额外反馈”的诊断身份。

暂不为 6 个任务训练复杂元学习器：独立任务样本太少，很容易学到偶然的任务标签。

## 12. 执行前后的完成标准

执行前：

- 确认三套权重和软件环境可用，保留精确版本与配置。
- 核对 6 个 OpenML Task、目标列、忽略列和 3 个官方外层索引。
- 保存协议与全部 split；固定主要指标、阈值、预算。
- 所有模型在接通单元中通过行数、类别顺序、有限数值及无标签泄漏检查。

执行后：

- 54 个正式单元有结果或明确失败记录；实际完成数可追溯。
- 预测文件能独立复算 metrics。
- ValSelect 的选择只由 validation 结果确定。
- Oracle、实际可执行选择和固定模型分开呈现。
- 结论包含正面结果、负面结果和未覆盖场景。
- 下一步的范围由预先写明的规则决定；任何协议改变另起版本。
